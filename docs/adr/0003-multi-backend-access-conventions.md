# Multi-Agent Backend Access Conventions

Status: accepted. Implemented by the Python Bridge since ADR-0004.

opencode, trae-cli, kiro-cli, and kimi all provide stdio ACP. Backend differences stay at the configuration and startup argv layer while reusing one ACP client. Backend-specific implementations are allowed only after measured protocol behavior proves incompatible. The third backend, kiro-cli, was added on 2026-09-12 with the v3 engine by default and tested on 2.21.4. The fourth backend, kimi, was added on 2026-09-13 with its native `kimi acp` server and tested on 0.42.0. Both passed revalidation without adapters.

Conventions:

- **Flat configuration**: `backend` is the dispatch key. Built-in argv values are opencode -> `opencode acp`, trae-cli -> `traecli acp serve`, kiro-cli -> `kiro-cli acp --agent-engine v3 --auth-method cli`, and kimi -> `kimi acp`. Repository-level `command` + `args` may override the whole argv, must be provided together, and do not receive appended default parameters. kiro-cli defaults to the v3 engine: v2 is legacy and will be removed, and in v3 the Agent actively reads Skill files through fs capability, while v2 relies on Skill tools absent from the ACP Session and nested Skill calls fail. `--auth-method cli` keeps authentication inside the subprocess; otherwise v3 expects `_kiro/auth/getAccessToken` and hangs when the client does not implement it. These were measured on 2.21.4. kimi's `kimi acp` is a native ACP server: logged-in hosts work directly; logged-out hosts receive terminal authMethods from initialize and must complete `kimi acp --login` device-code login first. This was measured on 0.42.0.
- **Startup interception for dangerous argv**: reject startup when argv contains parameters known to bypass the Permission Policy, including trae-cli `bypass_permissions`, opencode `--yolo`, and kiro-cli `--trust-all-tools` / `--trust-tools`, because bypassed tools never emit ACP permission requests. kiro-cli short option `-a` cannot be blocked by substring without too many false positives; allowed tools should be configured through host-level `allowedTools` in `~/.kiro/agents/*.json`, not argv.
- **Session binds backend**: state records the backend and full argv. Resume reuses the original backend and must not silently switch based on current defaults.
- **Minimal model branch**: trae-cli injects model through argv; opencode sets its `model` config option after `session/new`. kiro-cli uses the same configOption probing path and warns without switching if the backend does not provide a `model` option. kimi initialize returns no configOptions in 0.42.0 tests, so ACP cannot switch models per Session; the host `config.toml` `default_model` decides. When no model is specified, keep the backend default.
- **Revalidate measured assumptions per backend**: permission matching by `options[].kind`, rejection reason extraction, `session/load` semantics, and silent Turns after rejection cannot be assumed from the protocol name alone. kiro-cli revalidation on 2.21.4 with v3 found custom optionId strings, standard kind values including reject_always, valid kind matching, rejection reasons in `rawOutput.message` while opencode uses `rawOutput.error` and kiro v2 uses `content[]` text blocks, non-silent Agent output after rejection, and reliable cross-process `session/load`. kimi revalidation on 0.42.0 found a standard protocol surface for initialize/session/update/request_permission, but the host default allows file writes and does not trigger request_permission. Whether to ask is decided by host `~/.kimi-code/config.toml` permission, like opencode.json; argv-level `--yolo` is already intercepted. To verify the Bridge Permission Policy with kimi, first set host permission to ask mode.

## Consequences

- Adding a backend usually only requires default argv, model configuration branching, a dangerous-argv list, and one set of real-machine smoke evidence. kiro-cli on 2026-09-12 and kimi on 2026-09-13 validated this shape: the only protocol change that escaped the configuration layer was backend-neutral generalization of `_extract_tool_error`, which probes three rejection-reason locations without `if backend ==` branches.
- Users of `command`/`args` are responsible for the full argv, while still being subject to dangerous-parameter interception.
- trae-cli default ask mode was verified on a real machine on 2026-09-12: Edit triggers a permission request.
- kiro-cli revalidation was measured on 2026-09-12 with 2.21.4 v3 engine and wire-level stdio capture: optionId values are custom strings, kind matching holds, and `agent_message_chunk` uses standard `session/update`; `_kiro.dev/` extensions are only tool_call_chunk previews and metadata and can be ignored safely.
- kimi revalidation was measured on 2026-09-13 with 0.42.0: initialize returns `authMethods` for terminal login and is transparent when the host is already logged in; it returns no configOptions; Session startup actively reads repository `AGENTS.md` through fs capability by probing `.kimi-code/AGENTS.md`, `AGENTS.md`, and `agents.md`, where missing-file errors are acceptable; host default permission does not emit a permission request for file writes.
